# First-slice player import boundary

The browser player's `tools/import-packs.mjs` consumes the existing corpus and imports only the assets required by Hotel Dimensia, Turtle Hurdle, and Garden. This note records source handling; application implementation and pack registry remain in `business/zoombinis/`.

`tools/player_prepare.py` supplies an explicit one-game preparation fallback. It validates the supplied ISO's known SHA-256 before creating output, calls the existing `corpus.iso_files` reader, retains source byte ranges and per-file hashes, extracts only roles `game-data`, `game-runtime`, and `game-manual`, and invokes the corresponding canonical decoder. Installers and bundled demos are excluded. It never executes a source executable or installer. Preparation writes to a newly created `local/player-imports/<game>-<uuid>/` directory; an existing output directory is rejected. Canonical `local/discs`, `local/derived`, and `local/manifests` remain unchanged even if preparation fails. Successful preparation is retained as private research data; incomplete preparations are unregistered and can be inspected separately.

The explicit player command `npm run import -- --game mountain-rescue --iso /path/to/MountainRescue.iso` hashes the full supplied ISO and first tries verified canonical resources. If they are missing or fail verification, the helper prepares that supplied game into a separate corpus. No unspecified ISO is searched for or downloaded. Python with Pillow and numpy is an import dependency, never a browser-runtime dependency. `--python` and `ZOOMBINI_PYTHON` select the interpreter; the local bundled runtime is used when available.

The supported ISO/executable hashes are those already recorded in the three corpus extraction manifests. The importer checks both the ISO edition marker and the exact expected executable hash, then hashes every original source file referenced by the selected resources. Logical Journey and Island Odyssey selected archive slices are independently rehashed against their stored offsets and lengths. Mountain Rescue output images and Island Odyssey images/frames are checked against canonical decoder output hashes; copied pack outputs are hashed again. Logical Journey's selected background is additionally re-decoded from its preserved bitmap payload and checked for indexed pixels, dimensions, and every used palette color against the source palette. This establishes extraction/conversion integrity within the existing decoder boundary, not original-renderer visual equivalence.

Packs contain source backgrounds/icons plus **filtered** resource metadata. They preserve the selected originals' source hashes, ISO offsets, resource offsets, decoder metadata, frame identity, palette evidence where relevant, and decoder script hash. Unrelated whole-game manifests and large family test histories are not needed for these first slices. The pack schema remains 1 while the converter is `first-slices-2`. Fingerprints include the selected content hashes and scene bindings. Media and metadata stay under ignored `local/player-packs/` and outside the public application build.

The importer copies into an unregistered stage, validates its complete manifest and all outputs, then renames the immutable versioned directory and atomically replaces the registry. Failed stages are removed, old pack directories and registrations remain, and the newest version is registered before older versions for the same game. A directory lock serializes separate import processes. A lock remaining after process interruption is explicit and does not trigger automatic deletion of a possibly live owner's state. Importing several games is intentionally a sequence of per-game commits, not a claimed batch transaction.

The registry rejects unsafe resource paths, symlinks, duplicate IDs/resource paths, unsupported editions, inconsistent fingerprints, missing scene bindings, oversized files, and changed content. Runtime `registryReport` reports each missing or corrupt version independently, allowing healthy registered packs to remain available; malformed top-level registration remains an explicit error. Earlier pack versions stay accessible by exact ID for existing saves.

Validation performed for this change: importer help, successful existing-corpus import for all three games, successful explicit Mountain Rescue ISO hash/reuse path, and seven Node tests covering path/manifest guards, content corruption, isolated registration errors, repeat imports, retention of older registrations, failed import preservation, importer locking, and source-record field-order independence.

## Fresh ISO integration check

A full Island Odyssey ISO preparation ran through the actual importer fallback with an intentionally absent extracted corpus. Reproduce from the player directory with:

```sh
node tests/packs-fresh.mjs /path/to/IslandOdyssey.iso
```

The test creates an isolated research view and pack registries under this corpus's ignored `local/player-imports/`; its tools link is read-only usage of the canonical decoder directory. It independently builds an existing-corpus reference pack, invokes the explicit ISO fallback, verifies the fresh registered pack, and compares exact fingerprints. It does not register the test pack in the application's normal registry.

The passing run took **21.16 seconds**, extracted **68 game-relevant source files**, verified **1,447 exact resource payloads**, decoded and verified **13,921 PNGs**, and produced a **34-file, 380,154-byte** Garden pack. All required Garden resources decoded successfully. The decoder separately retained its eleven known unsupported AO palette variants elsewhere in the full game corpus; they are not Garden's required first-slice assets. Validation reported zero errors and retained the documented digit-leading XML-tag parsing diagnostic without changing source bytes.

The resulting pack ID was `island-odyssey-slices-v2-5176fe1bfb6a3651`, with the **same fingerprint as the independently imported existing corpus**. Hashes of the canonical Island extraction/asset/animation manifests, source executable, and application's pack registry were unchanged across the successful check. The complete result, logs, source hashes, decoder hash, and retained isolated preparation are identified in `local/player-imports/fresh-island-check-ASjPsj/fresh-import-result.json`.

The first fresh comparison found a real reproducibility defect: equivalent source metadata object fields had different insertion order between old and fresh extraction, making metadata bytes and pack fingerprints differ. The importer now canonicalizes provenance object keys before serialization. A standard pack test reverses the disc-manifest field order and checks that the resulting pack ID remains identical; the second full fresh Island run passed. Earlier pack IDs remain registered and usable.

Fresh full extraction/decode for Logical Journey and Mountain Rescue has not yet been repeated through this player helper. Their existing-corpus imports and the explicit Mountain Rescue ISO verification/reuse path have passed, but the all-three-edition clean-install release criterion remains open.
